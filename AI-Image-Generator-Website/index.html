Field guide - one file, generate.py
Repository My GitHub profile

A prompt goes in. The same PNG comes out, every time.

AI-Image-Generator is a small offline program I wrote in one Python file. It turns any text prompt into a PNG using math seeded by the prompt itself. No API key, no network call, no library beyond the Python standard library.

Entry 1What this is

I wanted to know if a text prompt could be an image seed, with nothing else involved. generate.py takes the SHA-256 hash of your prompt and treats it as the identity of the picture. Bytes 0 to 7 of that hash seed the random number generator that builds the picture field. Byte 8, on its own, picks which of the four color palettes the picture gets. I keep those two uses apart on purpose. In the campaign check of this repo, the same prompt at the same size produced a file with an identical md5 before and after a comment pass, because that sameness is the contract of the whole program.

From the seed, the program builds a plasma field out of sine waves, then shapes it three ways, which are the styles in entry 2. Every pixel is computed in plain Python, one row at a time, and the rows go into a PNG encoder I wrote by hand with struct and zlib. There is no model, no training data, and no image service behind it.

One line in my README needs a plain reading. It says Google AI Studio Imagen v4 Ultra, which was the picture I had in my head when I named the project. The code does not call Imagen, or Google, or anything else. It runs fully offline, as the README also says, and the PNG on your disk was drawn by the math in this one file.

Entry 2The three styles

plasma (the default)

Four seeded sine waves averaged together, then mapped through the palette. Soft fields and clouds. This is the style the README examples lean on for nebula type prompts.

--style plasma

waves

The plasma value is fed back into a sine, so the wave fronts bend instead of running straight. You get interference bands that curve around the field.

--style waves

orbit

A radial falloff around a seeded center point. The sine of the distance is folded with an absolute value, so the falloff reads as tight rings instead of soft bands.

--style orbit

All three styles draw their field seeds and their orbit center in the same fixed order. That is deliberate: if values were drawn only when a style needed them, switching styles on one prompt would change the field too, and comparing styles would stop meaning anything.

Entry 3The four palettes

Byte 8 of the prompt hash picks one of these, by taking the byte modulo 4. Each palette runs from its darkest stop to white, in order, because the color function walks the list as the field value rises.

Violet nebula

(10, 10, 26) - (91, 33, 182) - (167, 139, 250) - white

Deep ocean

(4, 20, 32) - (0, 119, 182) - (72, 202, 228) - white

Ember

(26, 8, 8) - (153, 27, 27) - (249, 115, 22) - (255, 237, 213)

Matrix green

(6, 26, 16) - (22, 101, 52) - (74, 222, 128) - (240, 253, 244)

Entry 4How to run it

# the two examples from my README
python3 generate.py "a violet nebula over a dark ocean"
python3 generate.py "geometric sunrise" --style waves --size 800

# name the output yourself when you want to
python3 generate.py "circuit dreams" --style orbit -o dreams.png
OptionWhat it does
--styleplasma, waves, or orbit. Default is plasma.
--sizeSquare size in pixels, 16 to 2048. Default is 512. Out of range exits with an error and code 1.
-o / --outputOutput file name. Without it, the name comes from the first 10 characters of the prompt hash, so the same prompt overwrites its own old file.

Cost grows with the square of the size, because every pixel is computed in Python. The size cap is checked before any work starts, so a typo like 20000 fails at once instead of running for a long time.

Entry 5Status, stated plainly

There is real code here, and it runs. While this page was being made, generate.py was run with the prompt "a violet nebula over a dark ocean" at size 64. It wrote image-68f08cce2c.png, 6,393 bytes, and the file header checked out as a valid PNG.

What it is not: it is not a hosted image service, it has no web page of its own, and this repo carries no LICENSE file, so there is no license badge on this page. The pictures are procedural art from a hash, not photographs and not model output. If you need a picture of a specific real thing, this is the wrong tool, and I would rather say that here than dress the repo up as something bigger.
